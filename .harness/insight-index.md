- 2026-08-16 · A `sys.modules` `os`-shim that neutralises `bin/sc`'s import-time auto-elevate by **name prefix** (`exec`/`spawn`/`fork`) leaves three POSIX process-start names live — `os.popen`, `os.posix_spawn`, `os.posix_spawnp` — and this is not theoretical: a `bin/sc` copy whose elevate guard called `os.popen` **started a shell** (probe artifact present on disk) while the harness reported `14 defined, 14 run, 14 passed`, **exit 0**, so a fully green test run can carry a process started from `bin/sc`'s import, and only an enumeration of every process-start name in `dir(os)` — not a prefix — closes it · evidence: committed-test-suite
- 2026-08-16 · `verify_all` A.1 cannot see the directory that holds every committed test artifact: its pathspec excludes `.harness/*` wholesale (a git pathspec `*` crosses `/`), and its regex is case-**sensitive**, so `restricted-network-regression.sh:43`'s `TOKEN='--i-will-destroy-this-vm'` matches only under `-i` — measured `case-sensitive: 0 / case-insensitive: 1` — which means any rule that relies on A.1 catching a fixture credential certifies nothing, and the constraint must be enforced by the artifact's own criterion instead · evidence: committed-test-suite
- 2026-08-16 · Deleting the `encoding="utf-8"` argument from `_write_private()`'s `fdopen` is **invisible** to an assertion that non-ASCII text reaches disk as UTF-8 on this host (`PASS … 5 text characters -> 11 UTF-8 bytes`), because the locale codec is already UTF-8; only a **codec substitution** (`latin-1`, which raises `UnicodeEncodeError` on `节点 ✓`) kills it — so a mutation sweep that deletes the argument rather than substituting the codec reports a **false kill** and certifies the opposite of what it claims · evidence: committed-test-suite
- 2026-08-16 · CPython's `backslashreplace` has **three** spellings and only one of them is legal JSON — `\xNN` (Latin-1 range) and `\UNNNNNNNN` (above the BMP) are not JSON escapes but `\uNNNN` (the rest of the BMP, i.e. **every CJK character**) is, so `sc config > file` under a non-UTF-8 stdout yields a file that **still parses** for a Chinese-tagged document and fails to parse for a `café` or emoji one; a two-spelling enumeration reads as complete and is wrong for the most common tag this project sees · evidence: state-file-contract-completion
- 2026-08-16 · `json.dumps()`'s `ensure_ascii=True` **default** puts pure ASCII on disk, so a locale fixture written as `json.dumps(doc).encode("utf-8")` contains no byte the codec under test can fail on and **passes identically on broken and fixed code** — `ensure_ascii=False` is what makes the control fail with `'ascii' codec can't decode byte 0xe8`, and this is a second, independent way for a locale criterion to certify nothing even after `PYTHONUTF8=0` is set correctly · evidence: state-file-contract-completion
- 2026-08-16 · A non-ASCII tag passed to a `bin/sc` fixture through `argv` under `LC_ALL=C` is decoded with `surrogateescape`, so the run dies inside the **fixture's own writer** (`UnicodeEncodeError: … surrogates not allowed`) before `sc` is reached — the failure looks like a product defect but is the harness's, and the only reliable transport is building the tag from source escapes and asserting it surrogate-free · evidence: state-file-contract-completion
- 2026-08-16 · `main()`'s read-only enumeration at `bin/sc:3769` gates `_init_files()` and `_resolve_clash_port()` **only** — `_load_lang()` runs on *both* arms — so the once-per-run `⚠️ Cannot use settings.json …` line is written by every command, `doctor` and `config` included; three documents in a row read that `if/else` as gating the announcement, because the two facts sit on adjacent lines and only one of them is enumerated · evidence: state-file-contract-completion
- 2026-08-16 · `generate_config()` raises `OverrideError` from **four** sites carrying four different `.path` values (override, settings, node store, and a composition fault carrying `None`), so a bare `except OverrideError:` at either call site is a **four-document catch** wearing the shape of a one-document one — it silently destroys the provenance the envelope exists to preserve, and the resulting build ships green because no criterion written for the document you just added measures the other three · evidence: state-file-contract-completion
- 2026-08-16 · `sing-box check -c` reads the file it is handed regardless of extension, **interpolates that path verbatim into its message**, and **colours its output even into a pipe** (`^[[31mFATAL^[[0m`) — so a check-before-write design may use any temp name, but must substitute the path back out of the message before a user sees it, and only removing the **complete** CSI sequence yields a pasteable line; measured against 1.13.15 with byte-identical documents at a `*.json` and a `config.json.check.*` name, and **no stub checker can exhibit any of the three** · evidence: validate-before-baseline

- 2026-08-16 · An exception raised in a `finally` clause propagates out of the **whole** `try` statement, so a `finally`'s own body is not protected by the `try` it belongs to — measured as `os.unlink(None)` raising `TypeError` **past** both an inner `except OSError` and an outer `except (OSError, ValueError)` and replacing the pending return — which makes "everything is inside one guarded region" false for exactly the block most likely to be edited later, and is the member three successive enumerations of `generate_config()`'s unguarded statements all omitted · evidence: validate-before-baseline

- 2026-08-16 · A `sys.modules` `os`-shim cannot deny a capability by attribute at all: `shim.__dict__.update(os.__dict__)` copies **function objects** whose `__globals__` is the real `os` module's dict, so `os._execvpe` and `os._spawnvef` — private, present in `dir(os)` today, matched by no public-name prefix — call the real `execv`/`fork` whatever the shim's attributes say, and a subject invoking `os._execvpe` **replaced the loading interpreter with `touch` at exit 0 with no summary line**; the same is true one hop out (`os.path.os._execvpe`), so adding names buys a spelling and never the capability · evidence: suite-guarantee-boundaries
- 2026-08-16 · Every module imported **before** a `sys.modules["os"]` shim keeps the real `os` and re-exports it: `posix.system is os.system` is `True` and `sys.modules["posix"]` is never replaced, so `import posix; posix.system(...)` is a **two-token** escape cheaper than `ctypes` or any attribute chain, while `subprocess` funnels `run`/`call`/`check_output` through the module-global `Popen` and is therefore closable at one choke point · evidence: suite-guarantee-boundaries
