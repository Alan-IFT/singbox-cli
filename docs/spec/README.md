# 项目 SPEC

这个目录是**项目级需求的真相源**。每个重要 feature 动手之前，应该有自己的 SPEC 文档。

## 文件命名

- `README.md` — 本文件，索引。
- `<feature>.md` — 每个 feature 一份 SPEC，例：`csv-export.md`、`auth-v2.md`。

## SPEC 应包含什么

- **目标**：一段话，业务理由。
- **范围**：做什么、不做什么。
- **约束**：技术、合规、时间。
- **验收标准**：可测试的条件。
- **风险 / 待解问题** 让用户决定。

## 风格

用确定性语言："必须"、"将"。避免"应该"、"可能"、"也许"。
拿不准时，写成 open question，动手前和用户一起解决。
