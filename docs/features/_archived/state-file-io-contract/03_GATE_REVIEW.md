## Pre-answered developer questions

| id | question | answer |
|---|---|---|
| Q-A | How does `_read_state` distinguish "caller supplied no default" from "caller supplied `None`"? | By the parameter default itself: `default is None` means *absent is a failure*. `load_settings()` passes `{}`, `load_nodes()` passes nothing. No caller wants `None` as the absent answer, so do **not** add a separate sentinel object. |
| Q-B | Does `_init_files()` seeding an absent `nodes.json` before an FR-6 abort violate "writes no state document in that run"? | No. FR-6's checked observable is AC-6's `settings.json` digest. `_init_files()` is `main()`'s initialising arm (`:3659`), reached before any handler, and this row touches it only through E-14. |
| Q-C | Does `encoding="utf-8"` on `os.fdopen(fd, "w")` disturb T-13's descriptor dance? | No. `os.fchmod(fd, CRED_MODE)` at `:508` has already made the mode exact one line earlier; `encoding=` only selects the codec of the `TextIOWrapper` that then takes ownership of the fd. Buffering, `newline` and `errors` are unchanged, so on a UTF-8 host the bytes are identical (AC-13), and `mkstemp`'s `0o600` stays an `open(2)` mode argument the umask can only narrow — never a chmod. |
| Q-D | Is K-2's ordering really necessary? | Only if both arms hang off one `try` — `UnicodeDecodeError` is a subclass of `ValueError`, so a `ValueError` arm placed first reports "not valid JSON" for a document that is not text. It is moot if you decode and parse in two separate `try` blocks, as `_load_override()` does at `:1484-1493`. Either shape is acceptable; `ValueError` before `UnicodeDecodeError` in one block is not. |
| Q-E | Is K-5's `getattr(e, "strerror", None) or str(e)` sufficient, not just necessary? | Yes. `UnicodeEncodeError` carries no `strerror` (so `e.strerror` raises `AttributeError` *inside* the handler, which is the bug Q-9 exists to prevent) and its `str()` is `'utf-8' codec can't encode …`; for an `OSError` whose `strerror` is `None` it falls through to `str(e)`. Both are non-empty, which is FR-11's requirement. |
| Q-F | Where does the lone-surrogate write actually raise, and is BC-11 still true? | Inside `_write_private`, at `fh.write(text)` — `json.dumps(..., ensure_ascii=False)` does not raise on a surrogate, the `TextIOWrapper` does. The `finally` then unlinks the temporary and `fd` is already `-1`, so the target is byte-identical and nothing survives. `except (OSError, ValueError)` catches it because `UnicodeEncodeError ⊂ ValueError`. |
| Q-G | Which command does AC-7 / V-7 drive? | Any non-doctor, non-config command; `sc ls` is cheapest. `_resolve_clash_port()` runs at `bin/sc:3661` for all of them, before the handler. |
| Q-H | GA-1 — does FR-11 reach `save_settings()`? | **No.** This diff provably does not change that function's failure surface (see C-11's ground), so "unchanged from HEAD" is true and RT-4 stands as filed. No budget relief is granted, because none is needed. |
| Q-I | GA-2 — is AC-13's fixture restriction legitimate? | **Legitimate in substance, wrong in its stated ground, and it must be narrowed in writing (C-5).** `sc` *can* author one non-ASCII settings value — `update_interval` at `bin/sc:3377` is copied verbatim from `argv` with no enum check — so the restriction must name the excluded keys instead of claiming no such value exists. |
| Q-J | GA-3 — is `_resolve_clash_port()`'s `except OverrideError` a fourth decide-site? | **No, the architect's reading holds:** the usability judgment was already made by `_read_state` and the "means empty" judgment by `_settings_or_empty()` earlier in the same function; this arm only decides *not to write*. But the count of three is only checkable by enumeration, which C-10 makes binding. |
| Q-K | Is reusing `OverrideError` for a state document legitimate, or does it mortgage T-24? | **Legitimate.** It is rule 85's "reuse an existing seam rather than add a parallel one": zero new keys, zero new arms, and 16 call sites served by an arm this diff does not touch. The cost to T-24 is bounded to one construction site (`_unusable()`, RT-1) and one arm it must not narrow — but the prose that names the class "a user override" must be corrected now (C-4), not left false. |
| Q-L | Is I-9's new key necessary, given NFR-2? | **Yes.** BC-6's fourth class (`{}` with no `nodes`) has no existing clause, and `the top level must be a JSON object` would be a false sentence for it. NFR-2 is amended by C-9; AC-17 already anticipated this case and governs. |
