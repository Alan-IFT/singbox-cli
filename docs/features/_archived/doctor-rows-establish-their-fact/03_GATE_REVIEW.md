| PQ-1 | Does `_doctor_ipv6()` calling `_dns_overlay(suppress)` break `sc doctor`'s process-wide read-only invariant, or introduce a second opinion? | No to both, **after** the signature change and only after it. `_dns_overlay(suppress)` then returns a dict literal built from `_aaaa_rule(suppress)` (`bin/sc:1743-1754`), which is pure — no I/O, no print, no `ipv6_decision()` call — so the doctor arm still reaches neither `_init_files()` nor `_resolve_clash_port()`, and the count of `ipv6_decision()` calls is unchanged in every command. The existing prohibition in `_doctor_ipv6()`'s docstring (`bin/sc:2685-2687`) exists solely because HEAD's overlay calls `ipv6_decision()` itself; E1 removes the reason and must remove the sentence in the same edit. |
| PQ-2 | Will a host with `telemetry: block` fail the new position test? | No, today. `_telemetry_overlay()` (`bin/sc:1881-1885`) uses `$before` anchored on `{"clash_mode": "Global"}`, and `_apply_directive` resolves that anchor by search (`bin/sc:1409-1418`, `:1435-1438`), so its rule lands at index ≥ 1 whatever `_dns_overlay()` prepended; `$prepend` puts the AAAA rule at index 0 (`bin/sc:1444-1445`) and `_filter_rules()` only ever removes rules and keeps the AAAA rule because it carries no `rule_set` (`bin/sc:1078-1099`). Only a user `override.json`, merged last at `bin/sc:2100`, can insert ahead of it. Assert this, do not assume it — BC-C. |
| PQ-3 | If the position test raises, how much of the report is lost? | One row. `_doctor_ipv6()` is its own single-row section in `DOCTOR_SECTIONS` (`bin/sc:2980`), and `cmd_doctor`'s per-section envelope (`bin/sc:3006-3013`) renders `[UNKNOWN] IPv6 (AAAA): this check could not run: '$prepend'`.
