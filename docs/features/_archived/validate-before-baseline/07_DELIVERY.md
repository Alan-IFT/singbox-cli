### What was actually wrong, and why it was worth a task

`generate_config()` wrote `config.json`, recorded its drift digest, and *then* asked the checker. On a rejection it printed a line and refused to restart — so the daemon kept serving its previous in-memory configuration and the run looked handled. It was not: `/etc/sing-box/config.json` now held a document `sing-box` refuses, `systemd/sing-box.service:9` reads exactly that file at **every** start under `Restart=on-failure`, and the weekly rule-set timer restarts on `changed and not gained` **without regenerating**. The failure was therefore *deferred and disconnected* — a reboot, a crash, `sc on`, or an unattended timer up to a week later. Stage 1 was told this was the diagnosis and **re-verified it first-hand rather than inheriting it**, then established the severity that the brief had asked it to test rather than assume. The baselined digest turned out to be the **milder** half (the record is literally true, and `sc doctor` still reports the invalidity through its own checker row) — **the harm is in the write, not in the record**, which is what shrank the fix to an ordering instead of growing it into a validation pipeline.

### The shape, and the alternatives that were priced and rejected

*Candidate → verdict → install → record.* The composed document goes to a fresh `O_EXCL` name in `config.json`'s **own** directory through the existing `_write_private()` — inheriting all five of T-13's guarantees rather than restating any — the checker is pointed at **that** file through the existing `_doctor_run()`, and `config.json` is replaced only by a verdict that is not *rejected*. No new function, class, module, file, key, flag, format or seam.

Rule 85 was run as a contest rather than quoted as a slogan. Stage 2 named four smaller alternatives; **stage 3 re-priced them itself** and upheld the `os.replace` shortcut as rejected on a ground stage 2 never stated — `config.json`'s mode, symlink and atomicity guarantees are pinned by the committed suite **only where `_write_private` is pinned**, so the second write buys **inherited coverage**, not just an invariant sentence — and then proved **no fifth shape exists** by exhausting the three degrees of freedom (what the checker is pointed at, who creates it, how it is named). The tempting one-liner was foreclosed at stage 1: moving only `_record_generated()` below the check leaves the landmine *and* makes `_drift_state()` accuse the user of a write `sc` performed.

**R-70 was folded in on a test, not for convenience.** Rule 85's first seam test does not join them — each half is individually coherent — but its duplicated-judgment test does: both are the same six lines and the same single judgement, *"what did the checker say, and what does the run do with each possible answer"*, which had two arms and sat after the irreversible act. Fixing R-70 alone would have put a guard on a call the R-73 fix then moved. The judgement gains a third arm: **cannot-validate is not invalid**, so an absent binary, an unexecutable one and undecodable output become one arm that installs, warns and succeeds — replacing three tracebacks.

### The rollback, which is the part of this task worth reading

It was routed to the **architect, not the developer**, and that routing is the finding: the code was *faithful* to the design, the hole was at a boundary the design drew, and the repair was a statement **K-1 forbade the developer to add**. ## Insight

- 2026-08-16 · `sing-box check -c` reads the file it is handed regardless of extension, **interpolates that path verbatim into its message**, and **colours its output even into a pipe** (`^[[31mFATAL^[[0m`) — so a check-before-write design may use any temp name, but must substitute the path back out of the message before a user sees it, and only removing the **complete** CSI sequence yields a pasteable line; measured against 1.13.15 with byte-identical documents at a `*.json` and a `config.json.check.*` name, and **no stub checker can exhibit any of the three** · evidence: validate-before-baseline
- 2026-08-16 · Replacing `config.json` with `os.replace(candidate, CFG_PATH)` instead of a second `_write_private()` call shows **0 observable differences across 13 cases** — a 9-case behavioural sweep plus a symlinked target, a `0666` target, `umask 000` and the real checker — while the committed suite reports `18 defined, 18 run, 18 passed`, so **no byte- or mode-comparing assertion can pin "the one writer installs the document"**; only a structural check (an `ast` clause or a grep) can, and until one exists that property is held by a decision record and nothing else · evidence: validate-before-baseline
- 2026-08-16 · An exception raised in a `finally` clause propagates out of the **whole** `try` statement, so a `finally`'s own body is not protected by the `try` it belongs to — measured as `os.unlink(None)` raising `TypeError` **past** both an inner `except OSError` and an outer `except (OSError, ValueError)` and replacing the pending return — which makes "everything is inside one guarded region" false for exactly the block most likely to be edited later, and is the member three successive enumerations of `generate_config()`'s unguarded statements all omitted · evidence: validate-before-baseline
- 2026-08-16 · `verify_all` B.4 compares the suite's passing count against `baseline.json`'s `test_count` and **never against that floor's own history**, so lowering `test_count` from 18 to 17 with 18 assertions present leaves B.4 **PASS** — the floor is a ratchet only by convention, and every criterion of the form "the floor does not fall" has had no control at all · evidence: validate-before-baseline
- 2026-08-16 · Absorbing a rejection arm into the sibling `try` whose `except OSError` handles the same call reads as an equivalent tidy-up and is not: a rejection whose own `sys.stderr.write` raises `OSError` is then caught, re-reported as a *different* verdict, and falls through to the install — measured as a build that returns `True`, installs the rejected document, re-baselines the drift digest and tells the user it *was installed without being checked*, with the committed suite fully green · evidence: validate-before-baseline
