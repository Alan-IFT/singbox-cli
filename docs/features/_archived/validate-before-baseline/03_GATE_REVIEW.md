## Pre-answered developer questions

| id | question | answer |
|---|---|---|
| PQ-1 | What shape must the `sc.subprocess` stub have? | Unchanged: `.returncode` plus `.stdout` as **bytes**, with `PIPE` / `STDOUT` attributes; `_doctor_run` does its own decode. Arm 4 binds **no** stub at all. |
| PQ-2 | Which argv index is the candidate, and why does that clause discriminate? | `[SB_BIN, "check", "-c", name]` makes it `argv[3]`; on HEAD that index holds `str(CFG_PATH)`. The directory half needs `os.path.dirname(argv[3])`, because the containment spelling is satisfied by every string beginning with the config path. |
| PQ-7 | Will V-14 see a second stderr line? | Yes, one **before** the write-failure line: the loader fixture's `rules/` is empty, so all four rule-sets are absent and `_warn_degraded()` (`bin/sc:1110-1126`) fires. `_warn_drift()` stays silent — `_config_digest()` cannot read `CFG_PATH` under an absent parent, so `_drift_state()` returns `None`. Assert on the line, not on the count (C-15). |
| PQ-8 | Does arm 4 actually reach `mkstemp`, or does something earlier fail? | Nothing earlier names `CFG_PATH.parent`: `load_settings()`, `load_nodes()`, `ruleset_report()`, `_compose()` and `save_nodes()` read other constants, and the drift quartet degrades to `None`. I-1's `mkstemp` is the first statement that touches the absent directory, which is why `_write_private` is never called — V-14's stated precondition holds. |
| PQ-9 | Where does arm 4 set `CFG_PATH`? | After `fixture()` returns, and still inside the run root: `fixture()`'s Path scan requires every `Path` attribute to resolve inside `ROOT`, and `Path.resolve()` is non-strict from 3.6, so an absent parent resolves either way. |
| PQ-10 | `UnboundLocalError` is a `NameError` — why not drop the sentinel and widen the `except`? | Because that spelling cannot name the state it is protecting, and it swallows any genuine `NameError` in the unlink block — a failure no arm reddens. The sentinel matches the file's own idiom at `bin/sc:533-541`, which is why it reads as a fence rather than as a workaround (H-5). |
| PQ-11 | May the `finally`'s inner `except` be widened to `(OSError, TypeError)` to be safe? | No. `OSError` alone is deliberate: a `TypeError`/`NameError` there must stay loud, and that is precisely what makes arm 4 a control instead of a description. |
| PQ-12 | Does the two-line delta change any round-1 V row's expected output? | No. Every path that reaches the checker binds a real `name`, so arms 1-3 and V-2…V-10 observe exactly what they observed in round 1; only the `mkstemp`-fails path is new, and V-14 is its row. |
