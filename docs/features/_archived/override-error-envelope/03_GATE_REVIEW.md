## Pre-answered developer questions

| id | question | answer |
|---|---|---|
| PQ-1 | Where exactly does the envelope's `try` open, given `override` may be `None`? | At `bin/sc:2069`, the `if override is not None:` line itself — so the whole `if` is inside the region while `override = _load_override()` (`:2036-2040`) and `config = _compose([...])` (`:2067-2068`) stay outside it. `override` is therefore always bound when the second arm evaluates `OVERRIDE_PATH if override is not None else None` (K-1, RK-11). |
| PQ-2 | Do I need `except OverrideError: raise` when `OverrideError` is already being raised inside? | Yes, and it is not redundant. `OverrideError` is a direct `Exception` subclass (`bin/sc:1223`), so without the explicit pass-through arm the `except Exception` arm swallows it and re-wraps it, destroying `e.path` and replacing a specific sentence with the generic one. Write it first, as a bare `raise`, and assign `e.path` in it for no exception and under no condition (K-2, K-5). |
| PQ-3 | E3 re-derives the loop around the target's type — does the directive-recognition order change? | No, and it must not. Evaluate `_directive_of(value, where)` once per `dict`-valued overlay key, **before** any test on `target` — a ternary guarded by `isinstance(value, dict)` at the top of the loop body does this. That is what keeps `at {at}: unknown directive …` and `at {at}: {name} cannot be combined with other keys …` firing ahead of the new array-position error at every target type (K-6, C-13). |
| PQ-4 | Which case does the new array arm change, and which cases must stay byte-for-byte as they are? | Changed: target value is a `list` and the overlay value is anything other than a directive object — object, scalar, `null`, bare array — all four now reach the one existing sentence at `bin/sc:1471-1473`. Unchanged, statement for statement: target is a `dict` with a plain-object overlay (recurse), target is absent with a bare array (accept, `deepcopy`), target is anything with a directive but is not a list (today's "can only be applied to an array that already exists"), and every scalar assignment including JSON `null` at a non-list key (out-of-scope 5). |
| PQ-5 | Does hoisting `json.dumps` above `_write_private` put credential bytes anywhere new? | No. The full serialised string already existed in the caller's frame before the hoist — it was `_write_private`'s argument — so the hoist only binds it to a name a few lines earlier. `_write_private()` stays the only writer, its temp-file-then-`0600`-then-content ordering is untouched, and `_record_generated()` still digests the file's bytes on disk through `_config_digest()`, never `text` (BC-5). |
| PQ-6 | `_filter_rules`'s call lines get re-indented by the envelope — does that break AC-8? | No. AC-8 measures the function's body, its signature and its **call sites' argument lists**; enclosing indentation is not part of any of the three (C-6). Change nothing between the parentheses at `:2097-2098` and the criterion holds. |
| PQ-7 | Why can't I just add `RecursionError` to `_load_override`'s existing `except ValueError` and drop E4? | Because `:1534-1537` wraps exactly one statement, `json.loads(text)`, which raises at least `RecursionError` (CPython's C scanner) and `MemoryError` (a pathological document inside the 1 MiB cap), neither of them a `ValueError` — and this repository has already measured that leaf enumerations at data boundaries ship incomplete (`.harness/rejected-decisions.md` §`clash-api-bare-except-and-leaf-enumeration`: four leaves filed, a fifth measured at stage 4, a sixth at stage 6). E4 closes the site as a region for +3 lines. |
| PQ-8 | What happens to the fixture when `sing-box` is not installed on the machine I test on? | `bin/sc:2111` has no `shutil.which` guard, so `subprocess.run([SB_BIN, …])` raises `FileNotFoundError` from **outside** the envelope and outside FR-2's region (F-14). For AC-4's byte comparison, stub `subprocess.run` or compare the emitted document before that line; do not widen the region to cover it — Q-8 rejected exactly that. |
