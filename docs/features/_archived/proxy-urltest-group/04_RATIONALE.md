## C-6 — the measurement that decided it

The gate declined to pick because the deciding fact — how long a DoH transport through a half-dead
member takes to error out — is unmeasured. It is still unmeasured. It stopped mattering, because the
option does not reach that connection at all.

Evidence, from the installed binary (same technique as E-4, on symbol names rather than strings):

```
$ strings -a /usr/local/bin/sing-box | grep -oE "github\.com/sagernet/sing-box/common/interrupt\.[A-Za-z()*.]+" | sort -u
…
github.com/sagernet/sing-box/common/interrupt.ContextWithIsExternalConnection
github.com/sagernet/sing-box/common/interrupt.IsExternalConnectionFromContext
github.com/sagernet/sing-box/common/interrupt.(*Group).Interrupt
github.com/sagernet/sing-box/common/interrupt.(*Group).NewConn
github.com/sagernet/sing-box/common/interrupt.(*Group).NewPacketConn
github.com/sagernet/sing-box/common/interrupt.groupConnItem
…
$ strings -a /usr/local/bin/sing-box | grep -oE "[A-Za-z/.]*[Ii]sExternalConnection[A-Za-z]*" | sort -u
box/common/interrupt.ContextWithIsExternalConnection
box/common/interrupt.IsExternalConnectionFromContext
interrupt.contextKeyIsExternalConnection
```

Reading: the group tracks every connection it dials (`(*Group).NewConn` / `NewPacketConn` →
`groupConnItem`) and, when the selection moves, `(*Group).Interrupt` closes them. `groupConnItem`
carries an *external* flag that arrives through a **context key** set by whoever dialled
(`ContextWithIsExternalConnection`); a connection sing-box originates for itself never has it. So the
`interrupt_exist_connections` boolean can only widen the interruption to connections that came from
an inbound — the internal ones go regardless. This is also what sing-box's own documentation says
("Only inbound connections are affected by this setting, internal connections will always be
interrupted"), which I did not treat as evidence on its own since the doc is not on this host.

The DoH transport to `remote_dns` is dialled by the DNS subsystem through `detour: proxy`, not by an
inbound. It is therefore in the always-interrupted class, and F-3's inversion — "name resolution
keeps riding the failed node after the data plane has moved" — does not occur.

That leaves I-13's original argument intact and un-inverted: on the group the switch is automatic and
can be triggered by a 51 ms improvement, so a user's own inbound-originated transfers should drain on
the old member rather than be killed. **Kept.** The emitted document is unchanged, so V-4 did not need
re-running for this decision; it was run in full regardless (7 documents, all as expected).

Corroboration that the option is at least *accepted* on a `urltest` here, had the decision gone the
other way — the binary's registered option struct is exactly the five keys I-6 emits plus this one:

```
outbound.Register[go.shape.struct { Outbounds []string "json:\"outbounds\""; URL string
"json:\"url,omitempty\""; Interval …Duration "json:\"interval,omitempty\""; Tolerance uint16
"json:\"tolerance,omitempty\""; IdleTimeout …Duration "json:\"idle_timeout,omitempty\"";
InterruptExistConnections bool "json:\"interrupt_exist_connections,omitempty\"" }]
```

I-6 therefore emits the group's **complete** option surface for this binary; there is no unstated key.

## A fixture artifact, investigated rather than assumed

V-8 drives `sc add` with a synthetic Reality share link whose `pbk=x`. The run prints
`Added: auto #2 (⚠️ config check failed — see \`sc log\`)`. Cause measured, not assumed: the same
`nodes.json` regenerated by the **HEAD clone** at the same fixture path fails identically —
`FATAL initialize outbound[N]: decode public_key: illegal base64 data at input byte 0`. It is the
fake public key in the fixture link, present at HEAD, and it is not what V-8 observes anyway (V-8
observes the minted tag, the selection and the emitted document, all of which are as required).

## Harness / safety record

One `harness.py` loader is shared by all four scripts, and it is the `docs/dev-map.md:109-135` recipe
verbatim — `assert os.geteuid() != 0`, an `os` shim whose `geteuid` returns 0 so the elevate branch is
not taken, the module `exec`'d, and `sys.modules["os"]` restored in a `finally` (S-1). It then
repoints all seven path constants under one `mkdtemp()` root and **asserts** each resolves inside it
(S-3), sets `SYSTEMD = OPENRC = False` (S-4) and `SB_BIN = /usr/local/bin/sing-box` (read-only).
`_init_files()` is never called (S-2) — fixtures write `nodes.json` directly. `main()` is never
driven either, precisely because it calls `_init_files()`; language is therefore set on the module and
each language case additionally asserts `t("Delay") == "延迟"` iff `LANG == "zh"`, so no Chinese
assertion can pass vacuously (S-8). The pristine baseline is a `git clone` of the repo, not a
worktree (S-8). The Clash API is a stub `HTTPServer` on an ephemeral port in every step that could
mutate anything; the live API was never contacted at all, not even for a `GET` (S-5). `TUN_IFACE` was
left alone — it is captured into `CONFIG_BASE` at import time and is not repointable afterwards.

Everything lives in the session scratchpad (`harness.py`, `v1.py`, `v_config.py`, `v_api.py`,
`v_upgrade.py`, `head-clone/`) and nothing was added to the repo (NG-9).
