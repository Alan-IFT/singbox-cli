## Boundary tests added

- Absent file; `chmod 000`; **`config.json` that is a directory** (EISDIR — a non-EACCES `OSError`); non-UTF-8 bytes.
- Empty file; valid UTF-8 that is not JSON; **a truncated document whose last complete token is a live credential** — nothing was printed, so BC-4's "the raw text is not printed" holds where it matters most.
- Top level `[]`, `42`, `null`, `true`, and **a bare string containing a credential** — all refused with one sentence and an empty stdout.
- `outbounds` absent; `outbounds` a string; **`outbounds` an object holding a credential**; an element that is a number; an element list of tag strings (the T-15 urltest shape).
- A key `sc` never emits inside an outbound; `transport.headers` with `Host` plus two arbitrary keys; **a credential under a visible container** (`tls.certificate`, `tls.reality.unknown_child`).
- Masked keys holding an int, `null`, a list, an object and `true` (BC-16 across every JSON type).
- **A key named `outbounds` that is not the outbounds array** — `strict` turns on below it, so the subtree is *over*-masked; the failure direction is readability, never disclosure.
- 200-level nesting (renders whole) and the crossover to `RecursionError` at ~1000 levels (QA-2).
- Unicode: a non-ASCII tag, an emoji, an embedded CR and a CSI sequence — all re-escaped by `json.dumps`, so no raw control byte reaches a non-TTY stdout.
- Concurrency: 40 reader processes against a writer doing `os.replace()` every ~1 ms (BC-11) — no mixture, no leak.
- Empty-string credential (**RES-5**): `outbounds.7.password` is `""` on disk and still renders `******`, so *unset* is indistinguishable from *set*. Confirmed as the decision FR-5 states, not an accident.
- Duplicate keys (**RES-2**): `{"log":…, "outbounds":[], "log":…}` renders only the **last** `log`; disclosed, not defended against, for the same reason BC-4 refuses to print unparseable text.
- Encoding (**RES-3 / RS-6 / GC-7, restated**): neither `CFG_PATH.read_text()` nor the `ensure_ascii=False` write names an encoding. Measured, not just restated: under `LC_ALL=C PYTHONCOERCECLOCALE=0 PYTHONUTF8=0 python3 -X utf8=0`, a **valid** document whose tag is `香港节点` yields `cannot read …: 'ascii' codec can't decode byte 0xe9 …`, exit 1 — one sentence, no traceback, because K-5 catches `ValueError`. A `C`/`POSIX`-locale host at the documented 3.6 floor is affected on the read; the write half is unreachable on a single-locale host (the read fails first), and the visible degradation there is the zh commentary rendering as `\uXXXX`. Pre-existing repo-wide class; **no code is bought for it** (D-6).
- Provenance window (**RES-1 / RS-3**): `_drift_state()` re-reads the file after `read_text()`, so a `sc reload` landing between them makes the provenance line describe a newer inode than the document printed. **Stated, not tested** — the window is a few hundred microseconds between two named calls and both outcomes are non-alarming. BC-11's atomicity, which is the part that matters, *was* tested above.
- Stdout teardown beyond BC-14: reader gone before the first byte (`2>&1 |` with an immediately-closing reader) → exit 120 five times out of five, no traceback (**RES-6 confirmed, milder than predicted**); `sc config >&-` → `AttributeError: 'NoneType' object has no attribute 'write'` (QA-3).
