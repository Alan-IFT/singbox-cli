## The recursion probe (QA-2), depth by depth

```
depth  500 → prints (514 564 B)      depth  900 → prints (1 646 164 B)
depth  990 → prints (1 988 974 B)    depth 1200 → RecursionError, exit 1, stdout 0 B
```

```
$ python3 runner.py RA config     (depth 2000)
Showing the configuration on disk: …/config.json
Node credentials are masked; a masked value shows as ******.
Traceback (most recent call last):
  File ".../bin/sc", line 2770, in cmd_config
    sys.stdout.write(json.dumps(_redact(doc, False),
  File ".../bin/sc", line 2719, in _redact
    out[k] = _redact(v, strict or k == "outbounds")
  [Previous line repeated 992 more times]
RecursionError: maximum recursion depth exceeded
```

The traceback is inside `_redact`, i.e. **`json.loads` had already parsed the document**. D-2's
premise ("`json.loads` raises it before `_redact()` is reached") is false on CPython, because
`json.loads` uses the C scanner (`_json`) whose depth budget is not the Python recursion limit, while
`_redact()` is pure Python. `grep -c QAxx` over the 27-line traceback returns **0** — no credential
byte is in it, and stdout stayed empty. Reaching this needs ~1000 levels of nesting, i.e. a
hand-written or override-supplied document; nothing `sc` composes comes close.

## The two stdout-teardown probes

```
$ runner.py R8 config 2>&1 | head -1     → sc exit 1, one clean line, no traceback
$ reader closed before the first write (2>&1 | true, ×5)  → exit 120, 120, 120, 120, 120
$ runner.py R1 config >&-  → AttributeError: 'NoneType' object has no attribute 'write', exit 1
$ runner.py R1 status >&- ; runner.py R1 help >&-         → exit 0, silent
```

Exit 120 is CPython's "failed to flush a standard stream at shutdown" status, so RES-6 is real but
milder than predicted: with **both** streams on a broken pipe nothing can be printed anyway and the
symptom is a non-standard exit status, not a traceback. The `>&-` asymmetry is `print()` (returns
silently when `sys.stdout is None`) versus `sys.stdout.write` (`AttributeError`), not a redaction or
contract failure.


criterion. Masking was unaffected.

## BC-11 under a real race

`vconc.py` runs a writer thread doing `os.replace()` (the same `rename(2)` `_write_private()` uses)
between two 105 KB documents distinguishable by `log.level`, every ~1 ms, while 40 `sc config`
processes run against it:

```
document sizes: A=105439 B=105439 bytes
runs=40  whole-A=23  whole-B=17  bad=0
BC-11 RESULT: PASS
```

Both documents were observed, so the race was live; every rendering parsed, carried exactly 800
outbounds, masked all 800 passwords, contained no `QAxxCONCPWxx` byte and exited 0. RES-1's narrower
claim — that `_drift_state()` reads the file *again* after `read_text()`, so the provenance line can
describe the newer inode — is **stated, not tested**: catching it needs the replace to land inside a
window of a few hundred microseconds between two specific calls, and both outcomes are non-alarming.
