### What shipped, and what was refuted

**The goal's second clause was partly false at HEAD, and stage 1 caught it before any code was written** — the T-18 precedent applied a second time. `cmd_update_rules()` has ended `if failed: sys.exit(<str>)` since T-02 (`ab4e4a4`), which exits 1, and the unit is `Type=oneshot` with one un-prefixed `ExecStart`, no `SuccessExitStatus=` and no `Restart=`; a failed **download** therefore already recorded a failed unit. Implementing the clause as briefed would have re-fixed a working path. What was actually broken were two states nobody had enumerated, both confirmed against a pristine HEAD clone (`84c8d8b`): a run that gains rule-sets and then fails `generate_config()` or `sing-box check` exited **0** *and unconditionally printed* `config regenerated`; and `restart_service()` used `check=False`, so a failed restart was unobserved and the run still claimed `sing-box restarted to load them`. Both are exit-0 lies, and both now exit 1 and claim neither.

**Half 1 reused the seam instead of adding one.** The timestamp is read by `os.fstat(fh.fileno())` **inside** `ruleset_state()`'s existing `with path.open("rb")` block, so it describes the same bytes that produced the status and the digest, and the binding DIGEST CONTRACT extends to one chain: `mtime is None ⟺ size is None ⟺ digest is None ⟺ status in {absent, unreadable}`. `st_size` still appears in no code. `_status_view()`'s **return** stayed at 3 elements, so `_runtime_overlay()`, `usable_tags()` and `_warn_degraded()` needed no edit and FR-5 cost zero lines — the case that docstring was written for. One renderer `_age_text(mtime)` sits beside `_status_text()` with one call site and no command-specific argument, so **T-20 consumes it by calling it inside `_doctor_rulesets()`'s existing loop** rather than deriving an age a second way.

**Half 2 is one determination.** `ok = not failed and regen_ok and restarted is not False`, with `restarted` tri-state, feeds both the outcome sentence and a single `sys.exit(1)`. The outcome set grew from three members to four — one truthful variant for the failed restart — and T-10's "exactly one apply per run", its conditional restart and T-02's recovery regeneration ahead of the exit all survive byte-for-byte.

**Rule 85 was tested rather than asserted, per half.** Stage 2 named the smaller alternative for each (a display-site `os.stat()`; fixing only the regeneration claim) and said what the extra code buys; stage 3 tested both against the code. Half 1's stated reason turned out **partly mis-argued** — the replace-between-read-and-stat race is real in mechanism but low-materiality, and what actually carries the widening is FR-1/AC-S1, `docs/dev-map.md`'s standing "never form a second opinion", and T-20 as a *nameable* future edit. Half 2's answer stood: the smaller design satisfies strictly less, and the restart clause is owner-stated in the goal sentence, not stage-1 invention. C-6 then put a hard ceiling of `bin/sc` **+80/−30** on the result; it landed at **+80/−29**.

**One DESIGN DRIFT, accepted, and it is the most valuable thing stage 4 produced.** Gate answer A-3 asserted that replacing `sys.exit(<str>)` with `sys.stderr.write` leaves the interleaving unchanged. The developer measured it and found the opposite: the interpreter flushes stdout *before* printing `SystemExit`'s string, while an in-run `sys.stderr.write` overtakes still-buffered stdout — the merged `2>&1` capture `install.sh:567` records put the aggregate ahead of the buffered output and **split the fourth per-file line in two**. The fix is one line, `sys.stdout.flush()` at `bin/sc:2869`. Stage 5 adjudicated it independently (explicitly not on grounds of size: rejecting it would have shipped a visible reordering of a stream FR-9/BC-8 *freeze*, honouring K-13's letter while defeating its purpose), and **stage 6 proved the check is live** with a mutant candidate: with that one line deleted, the capture differs from HEAD at byte 836, reproducing the transcript exactly.
